# Research Deliverable — the cloud-authored document (design + build spec)

Status: **DESIGN LOCKED 2026-06-30** (Lucas). Built foundation in place; the deliverable build (Slices A/B/C)
is the next work. This doc is the spec so it survives a compact.

## The vision (Lucas, verbatim intent)
Every research project produces ONE document that the **cloud writes end to end** ("cloud models need to be
writing everything"):
- **Page 1 = the PLAN** (objective, approach, the targets, which databases will be checked, what to gather).
- **Then the PRODUCT** — the profiles / findings themselves.
- **Citations + sources** throughout; every claim traceable.
- **Professional, cleanly read.**
Built by the flow: **unify existing research → check ALL databases (known→unknown) → compose the document**,
and it should **grow live** on the Canvas as it's built.

This is the determinism law at the deliverable: the cloud GENERATES the document; the program orchestrates +
guarantees completeness. The deterministic lossless stitch (lib/assemble) becomes the **completeness ORACLE**,
not the visible output.

## Maps to the pillars ([[verifiable-research-track]])

  estimate; this makes the plan a STRUCTURED object.

- **Pillar 3** — cloud-authored, completeness-gated document (Slice A).

## The build — three slices, in order
### Slice A — cloud-authored document + plan page (Pillar 0 + 3)
1. **Structured plan** generated by the cloud at project start: { objective, approach, targets[], databases-to-
   check[], facets[], est }. Stored on the focus (focus.<id>.plan). Reviewable (the readback shows it; the
   correction handler can edit it). Becomes page 1.
2. **Cloud composer** (replaces the visible deterministic stitch as OUTPUT): at finalize AND periodically, the
   cloud composes the whole professional document — page 1 plan → org profiles — from the per-org sections.
   COMPLETENESS-GATED: verify every covered org heading is present; patch any the cloud dropped from the
   lossless sections (the stitch is the oracle). CHUNK for large runs (map-reduce compose) so no single call
   truncates; size num_predict to the document.
3. Wire into condenseRun (it already writes the dossier file + emits to canvas) → emit the COMPOSED document.

### Slice B — citations / source trail (Pillar 1)
1. Each research pass records its real provenance — URL, the Echo tool + exact record pulled, the evidence
   snippet — into a per-run ledger (focus.<id>.sources or a sidecar). Echo has record_web_source/save_source/
   cite tools to leverage; the deep lane already touches authoritative sources (heritage.org 990, FEC) to RECORD.
2. The composer renders inline citations + a Sources section so every claim is traceable.

### Slice C — live-grow display (#2)
1. Re-run the compose on a cadence during the run and UPDATE the Canvas document block as it grows (re-compose
   → saga_canvas_update_block). Reuses the existing canvas emit (studio/canvas_emit) — NO new canvas UI needed;
   it's "more passes of the combining cloud call," which Lucas anticipated. Doubles as the on-track signal +
   confirms the deep/second track is producing.
