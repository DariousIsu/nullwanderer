# Zoe Canvas ↔ Research / Deliverable Engine — Integration Notes

Handoff from the directed-research/deliverable engine (built in `main.js` + `lib/research.js` +
`lib/condense.js` + `lib/focus.js`) to the **Zoe Canvas** suite (Side Quest surface that renders +
drives Echo's saga canvas: `tenant_rainey.canvas_tabs` / `canvas_blocks`).

These notes describe the SEAMS and CONTRACTS only — the canvas suite owns the saga store, the
render surface, and the `saga_canvas_*` write calls. My engine just needs to hand it the right
content at the right moments and stop voicing big output through the chat.

---

## 1. Determinism-law boundary (this is the load-bearing part)

Three tiers, already physically separated in the code — the canvas must preserve this split:

| Tier | Who | Where | Register | Reaches canvas? |
|---|---|---|---|---|
| **Orchestrator** | the Zoe *program* (deterministic control flow) | the driver loop, the focus state machine, the covered-set / target advance, file+meta writes, the "emit a block now" decision | n/a (code) | decides WHEN, never generates content |
| **Caged generation leaves** | cloud reasoner (gpt-oss:120b) via `condenseComplete()` | `buildOrganizeTargetPrompt` / `buildCondensePrompt` / `statusReport` | **professional / work-product** (grounded, schema-locked, no persona) | **YES — this is the canvas content** |
| **Companion voice** | Dans 24b (local) | the chat reply only | Zoe persona | **NO — never deliverable content; only the short pointer** |

The key fact for the port: **the deliverable content is ALREADY generated by the caged cloud
leaves in professional register.** The organize/condense/status prompts produce clean schema
(`## Org\n- **Focus:** … - **Key people:** … - **Contact:** …`), grounded, with "no initials/
placeholders → not found" and leaked-JSON stripping enforced. The canvas should consume *that*
output verbatim. The only thing that must never reach the canvas is the Dans-voiced chat string.

So "professional voice on the canvas" requires **no new model wiring** — just route the existing
reasoner-leaf output to blocks instead of (or in addition to) the markdown file + chat.

## 2. Generation leaves = the canvas's content sources

All in `main.js`, all call `condenseComplete(messages, {numPredict})` (the reasoner cloud call —
`models.sources()` cloud tier + `subconsciousModel()` = gpt-oss:120b). Prompt builders are pure in
`lib/research.js` / `lib/condense.js` (offline-tested).

1. **Per-target organized section** — `runDirectedResearchPass()`, on a target completing:
   `buildOrganizeTargetPrompt({target, raw})` → one clean `## <Org>` section (Focus / Key people /
   Contact / Positions / Funding). Currently appended to the deliverable file. **This is the natural
   per-block unit** — one DOC block per organization, emitted live as the run advances.
2. **End-of-run dossier** — `condenseRun(focus)`, on focus close: reads the whole deliverable file,
   `buildCondensePrompt` (map-reduce via `chunkForCondense` + `buildMergePrompt` if large) → the
   consolidated dossier (Summary + per-org sections + a **Gaps** list). **This is the final
   schema-locked deliverable** (maps to a `saga_render_*` renderer, e.g. executive briefing / research
   dossier).
3. **Status/progress report** — `statusReport(focus)`: reasoner over the live state → a crisp progress
   update. Feeds a JOB/RESEARCH status block or a metric_card; also drives the chat pointer.

## 3. Orchestration seams (exact insertion points to emit a block)

Add a single thin emit at each seam (see §8 for the helper). Do NOT scatter `saga_canvas_*` calls.

- **`main.js` `runDirectedResearchPass(focus)`** — right after the per-target organize +
  `filesLib.dispatch({tag:'file-append', …})` (where `progressed=true`, target completed):
  → emit a DOC **text/markdown block** with the organized section, into the focus's tab.
  This is what makes the canvas *live-update* as she works (Lucas's "show her work" ask).
- **`main.js` `condenseRun(focus)`** — after the dossier is written + `research.last_dossier` meta set:
  → emit/replace the **deliverable block(s)** (DOC mode, schema-locked renderer) + a metric_card with
  the final count. Mark the tab "complete".
- **`main.js` `statusReport(focus)`** (called from the status chat block, see §7) — optional: write a
  JOB status block so the canvas reflects progress even between target completions.
- **Counts / list** — the covered set is deterministic (`focus.<id>.covered`); emit a **metric_card**
  (N organizations) + a **table** (Org | Focus | Key people | Contact) without a model call.
- **Visual aid (the "interconnectedness via shared personnel" synthesis)** — ILLUSTRATIVE mode
  **knowledge_graph** block: orgs + people as nodes, shared-personnel as edges. The program requests
  it; a caged cloud leaf produces the node/edge JSON in professional register.

## 4. State / read contract (what the canvas can pull from my side)

All keyed by the directed focus id (`focus.<id>` is the natural tab key). Meta is SQLite `meta`
table (`db.getMeta`):

| Key / artifact | Meaning | Canvas use |
|---|---|---|
| `focus_state` (JSON `{id,ticks,strikes,directed}`) | the active directed run | which tab is live |
| open_thread row `focus.content` | the task goal | tab title / RESEARCH header |
| `focus.<id>.covered` (JSON string[]) | completed org names | metric_card + table rows |
| `focus.<id>.target` (JSON `{name,passes,facets,raw}`) | current org + depth | live "researching X (pass N)" status |
| `focus.<id>.file` | `notes/directed-<id>.md` (the appended deliverable) | source markdown if pulling from file |
| `focus.<id>.clarifications` (JSON string[]) | Lucas's mid-run refinements | shown as applied guidance |
| `research.last_dossier` (JSON `{focusId,path,goal}`) | the condensed deliverable | the finished DOC deliverable |
| `data/zoe_workspace/notes/directed-<id>.md` / `…-dossier.md` | durable file artifacts | mirror / fallback render source |

The files remain the durable artifact regardless of the canvas — keep them; the canvas is the live
render, not the system of record.

## 6. Tab / block model (recommended)

- **One tab per directed focus** (key = focus id; title = the goal). Mode = **RESEARCH/JOB while
  running → DOC deliverable on condense**.
- **Blocks stream vertically, one per organization**, appended live as targets complete (matches the
  driver's depth-first cadence: a block lands every few minutes when an org saturates). This gives the
  live-updating canvas Lucas asked for.
- On `condenseRun`, either (a) add a DOC "Final dossier" deliverable block at the top, or (b) collapse
  the per-org blocks into the schema-locked renderer. Your call (see §9).

## 7. Chat-pointer change (the other half of Lucas's ask: big output OFF chat)

The seam already exists. In `main.js` the status/list path is gated by `_isStatusReq` /
`statusHandled`, and the directed-task acceptance by the directed-setup block. **Today these inject
the full list/deliverable into `composedUserMessage` for Dans to voice** — that's the truncation/
confab surface Lucas is removing.

Change at these seams (once the canvas exists): instead of injecting the full content, inject a SHORT
pointer directive — e.g. `[Tell ${userName} briefly: the full <N>-org dossier is in the Canvas tab
"<goal>". Give the one-line headline; do NOT recite the list.]`. The deterministic covered-list +
the reasoner deliverable go to the canvas; Dans only points. (The leaked-directive strip `_DIRSIG`
and the deterministic covered-list builder are already in place and should stay.)

This is the concrete behavioral contract: **synthesis/lists/dossiers → canvas; chat → pointer.**

## 8. Recommended write path

Wrap all canvas writes in ONE thin helper on my side so the determinism boundary is a single
function and the seams stay clean:

```
// main.js — orchestrator emits a professional-register block; canvas suite maps + writes to saga.
async function canvasEmit({ tabKey, title, mode, blockType, content, meta }) { … }
```

Two viable implementations (canvas suite picks):
- **(A) Direct to Echo saga store** via `saga_canvas_open_tab` / `saga_canvas_add_block` /
  `saga_canvas_update_block`. Reachable from Side Quest TODAY through the Echo suit
  (`echoSuit.routeNeed` / the operator's `echo` tool) — no new transport. Cleanest if the canvas
  store is authoritative.
- **(B) Event seam** — `canvasEmit` posts a structured deliverable event (tabKey, kind, blockType,
  content) that the Canvas suite consumes and writes. Decouples my engine from saga's schema.

**Recommendation: (A)** — the saga store is already the system of record the canvas renders from
(`tenant_rainey.canvas_tabs/blocks`), and Side Quest already has the Echo path. My engine calls
`saga_canvas_*` at the §3 seams; the canvas suite just renders the store. One source of truth.

## 9. Open decisions for the canvas builder

1. **Tab granularity** — one tab per focus (recommended) vs one per deliverable kind.
2. **Per-org blocks vs one growing DOC** — streaming per-org blocks gives the live feel; the final
   condense can collapse them or sit on top. Which is canonical?
3. **Who triggers visual aids** — does the orchestrator decide "make a shared-personnel KG now," or
   does a caged cloud leaf propose the aid? (Determinism-law leans orchestrator-decides, cloud-fills.)
4. **Status block vs chat pointer** — is the live progress a canvas JOB block, the chat pointer, or
   both?
5. **Write path A vs B** (§8) — confirm whether Side Quest calls `saga_canvas_*` directly.

## 10. Don't-break list (state this session established)

- Caged leaves only (`condenseComplete` reasoner) generate canvas content; **never Dans**.
- Keep the grounding hardening that feeds the canvas: no initials/placeholders → "not found";
  leaked-JSON strip in `research.parsePass`; deterministic covered-list (no model) for counts/tables.
- Keep the deliverable FILES (`notes/directed-<id>*.md`) as durable artifacts.
- Heavy non-public tools stay OFF the automatic track (Lucas, 2026-06-29) — unchanged by the canvas.
